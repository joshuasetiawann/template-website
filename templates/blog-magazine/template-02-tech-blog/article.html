We Fine-Tuned a 3B Model on Our Docs. It Beat Search.

A weekend experiment with embeddings, one consumer GPU and 80k internal pages — plus the eval harness that kept us honest.

DK

Dana Kovac

Jun 4, 2026·11 min read

We kept hitting the same wall in production, so we did the unglamorous thing and measured it. A weekend experiment with embeddings, one consumer GPU and 80k internal pages — plus the eval harness that kept us honest.

What follows is less a verdict than a working argument, assembled from notes, false starts and one or two opinions I have since revised. The headline is up top; everything below it has to earn the claim or quietly take it back.

What the profiler actually showed

We started where every honest performance story starts: with a flame graph and a humbling. The bottleneck was never the glamorous part. It sat three layers down, in a retry loop nobody had touched since the second sprint.

The fix was boring, which is the highest compliment I can pay it. We deleted more code than we wrote, moved one boundary, and watched the p95 fall off a cliff. Boring fixes are the ones that survive the next on-call rotation.

What surprised the team was how much of our 'scaling problem' was really a defaults problem. Sensible defaults, set once and forgotten, were quietly costing us a six-figure cloud bill and a reputation for being slow.

What we changed, in priority order

  • Measured before touching anything — the tape measure has no incentive to flatter the architect.
  • Moved the expensive work off the request path and into a queue we could actually reason about.
  • Wrote the regression test first, so the win could not quietly un-win itself in three months.

Where the architecture goes next

Be patient with the boring middle. Beginnings are theatrical and endings are quotable, but the middle is where the real decisions live, unglamorous and undocumented. The block below is the part I would clip and keep.

bench.js
// the eval harness that kept us honest
async function bench(model, queries) {
  const hits = [];
  for (const q of queries) {
    const t0 = performance.now();
    const top = await model.retrieve(q.text, { k: 5 });
    hits.push({
      q: q.id,
      ms: performance.now() - t0,
      ok: top.some((d) => d.id === q.gold),
    });
  }
  const recall = hits.filter((h) => h.ok).length / hits.length;
  return { recall, p95: percentile(hits.map((h) => h.ms), 95) };
}

Ship the boring fix. File the postmortem. The clever rewrite can wait for a quarter when production is not on fire and the calendar is, for once, merciful.
