Event pipeline rebuild

Kafka-based pipeline handling 40k events/sec with exactly-once semantics; p99 latency cut 8x.

Overview

Overview

Lumeris’s event pipeline was a nightly batch pretending to be real-time. I led the rebuild to a Kafka-based system handling 40k events per second.

Exactly-once semantics where they matter, idempotent consumers everywhere else, and failure drills that prove the guarantees instead of asserting them.

The brief

The challenge

The migration ran shadow for six weeks — same events, both systems, diffed nightly. We cut over the day the diff stayed empty for a week.

Method

The approach

  1. 01

    Write the design doc

    Problem, constraints, two rejected alternatives and the failure modes — argued in comments before any code exists.

  2. 02

    De-risk the scary part

    A throwaway spike on the riskiest assumption: load test it, kill -9 it, partition it. Reality votes first.

  3. 03

    Build boring, instrument everything

    Small PRs, feature flags, metrics and traces from day one. The dashboard ships before the feature.

  4. 04

    Migrate without drama

    Shadow traffic, gradual cutover, instant rollback. The old path is deleted only after a quiet on-call week.
