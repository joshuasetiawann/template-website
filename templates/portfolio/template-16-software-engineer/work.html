How I work

The approach

Different projects, same backbone. This is roughly how the work happens.

  1. 01

    Spec

    Write the design doc first: the invariants, the failure modes, the rollback. The hard thinking belongs before the code.

  2. 02

    Shadow

    Run the new path beside the old one, diffed continuously, until the difference is boring.

  3. 03

    Cut over

    Switch when the data says it is safe, with a rollback one command away and dashboards watching.

  4. 04

    Operate

    Runbooks, alerts that mean something, and load tests that keep the guarantees honest over time.
