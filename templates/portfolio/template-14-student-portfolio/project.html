Overview

Overview

CampusEats started as a 36-hour hackathon entry: end-of-day food from campus cafés matched to students within walking distance.

We won the sustainability track, then spent a term making it real — two cafés, pickup windows, and a points system the union sponsors.

The brief

The challenge

The hackathon version matched perfectly and worked never. Making pickup actually happen — humans, timings, unsold trays — was the real project.

Method

The approach

  1. 01

    Ask around first

    Corridor interviews and quick surveys before any code. Most student projects die from solving imaginary problems.

  2. 02

    Prototype the risky bit

    Build the scariest assumption first — the matching logic, the sensor read, the API — before any polish.

  3. 03

    Test on real people

    Flatmates, classmates, strangers in the library café. Five users finding the same problem beats fifty opinions.

  4. 04

    Ship & write it up

    Deploy it, present it, document what failed honestly. The write-up is where the grade and the learning live.
