How I work

The approach

Different projects, same backbone. This is roughly how the work happens.

  1. 01

    Question

    Start from a real problem and a real user — even a coursework brief gets better when someone actually needs it solved.

  2. 02

    Sketch

    Rough, fast and on paper. I would rather throw away ten bad ideas early than polish one too soon.

  3. 03

    Build

    A working prototype, not a mockup. Code teaches you where the design was lying.

  4. 04

    Reflect

    Test with classmates, write up what I learned, and carry the lesson into the next project.
